Ranking Pages for Content Refresh

A FlyRank Content-Refresh Modeling Study

Abstract

This study asks whether a machine-learning model can rank pages that are likely to be declining using observable content and search-performance signals. The analysis uses the anonymized FlyRank starter dataset of approximately 30,000 pages and defines the starter decline label from the observed trend direction.

A Decision Tree is compared with a transparent stale-and-visible hand-rule baseline using Precision@50 under a client-grouped holdout split. The resulting ranking is treated as directional decision-support for prioritizing review rather than as proof of future traffic outcomes or a causal effect.

1. Research Question and Decision

Research question: Can a machine-learning model identify and rank pages that are likely to be declining using observable content and search-performance signals?

Decision supported: The analysis supports prioritizing pages for SEO/review when a team has more pages to inspect than it can review manually.

The main evaluation metric is Precision@50. This measures the fraction of actually declining pages among the first 50 pages selected by the ranking.

2. Data

The analysis uses the anonymized FlyRank starter dataset, a small public-safe development slice of approximately 30,000 pseudonymized pages. The work uses the flat starter CSV rather than production warehouse tables or private client-level sources.

The final model uses six observable signals:

  • content_age_days
  • days_since_last_update
  • impressions_90d
  • avg_position
  • ctr
  • word_count

The starter decline label is derived from trend_direction: a page is labelled declining when trend_direction is down.

Rows missing required modeling fields are excluded from the modeling sample. Client names, raw URLs, private queries, titles, and other private identifiers are not used in the paper.

3. Methodology

3.1 Model

A Decision Tree is used because it can represent simple non-linear relationships while remaining relatively easy to interpret. The model is configured with a maximum depth of 4 and balanced class weights.

3.2 Baseline

The baseline is a transparent hand rule. A page is considered a candidate when it is stale (days_since_last_update >= 180) and visible (impressions_90d >= 500). Candidate pages are ranked by impressions_90d.

3.3 Validation

Validation uses a client-grouped holdout. Approximately 20% of clients are held out for testing, so pages from the same client do not appear in both training and test data. This is more conservative than a simple random row split because it tests the model on unseen clients.

3.4 Leakage Checks

The target label and client identifier are excluded from the feature set. Trend-derived fields used to construct the target are not predictors. The train/test client intersection is checked and must equal zero.

4. Results

Both methods were evaluated on the same client-grouped test split.

Method Precision@50 Interpretation
Week-4 hand-rule baseline 0.56 Reference prioritization rule
Decision Tree 0.60 Learned ranking model
Observed result: On the tested client-grouped split, the Decision Tree measured higher Precision@50 than the Week-4 baseline. This is an observed result on the tested sample and should be interpreted as directional evidence for prioritization rather than a guarantee of future performance.

5. Limitations

  • The decline label is a proxy derived from the observed trend_direction field rather than a direct future-outcome label.
  • The analysis uses the anonymized starter slice rather than the full production-scale warehouse.
  • A high model score does not prove that a page needs a particular content change or that changing it will improve traffic.
  • Measured performance depends on the selected features, split, metric, and sample.
  • Search behavior, seasonality, content mix, and data distribution can change, so recommendations may become stale.
  • Review is required before making substantive content, SEO, publishing, deletion, or redirect decisions.

6. Ranked Recommendations

The action playbook ranks pages by the Decision Tree's estimated decline probability. Reason codes provide short, clear explanations based on observable signals.

Reason Code Observable Signal
STALE_CONTENT days_since_last_update >= 180
HIGH_VISIBILITY impressions_90d >= 500
LOWER_RANKING avg_position >= 10
LOW_CTR ctr < 0.03
SHORT_CONTENT word_count < 500

Recommended workflow: review the highest-scored pages first; inspect current content, search intent, recent changes, seasonality, ranking context, and related pages; then decide whether an action is appropriate.

No-go list: the model should not automatically publish, delete, redirect, substantially rewrite, or make claims about penalties or future traffic. Its role is prioritization and decision-support.
